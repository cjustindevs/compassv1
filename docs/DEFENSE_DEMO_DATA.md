# One-time additional defense history

Use the existing Neon database and existing COMPASS accounts. This adds historical sample content for the October 16, 2026 demonstration. No new account/password, database or paid service is needed.

## Run during Render deployment

After deploying the code, add this Render Environment variable and save/redeploy:

```dotenv
RUN_DEFENSE_DEMO=true
```

The startup script runs `php artisan compass:seed-defense --apply --no-interaction` against the database already configured on Render. Leave all current Neon connection settings unchanged. Look for `Defense demo batch added: defense-2026-10-16-v1` in startup logs and its table counts. After success, set `RUN_DEFENSE_DEMO=false`. Repeat startups skip the same batch even if the flag is left enabled.

This is separate from `RUN_SEED_DEMO`; do not enable the general seeders for this import. A failure rolls back the batch and normal app startup continues. Missing active role profiles or missing current migrations must be resolved before retrying. No reset/fresh/truncate command is used.

## Added records

- 40 finished chat sessions and 80 explicitly labeled sample messages, across the preceding 29 days.
- 40 sample session reports and 40 categorical experience ratings using the current scoring function.
- 10 completed referrals, past completed appointments, Professional notes, referral-specific synthetic consent events and confirmed completion reports.
- 4 resolved historical emergency examples linked to those referrals.
- An append-only audit manifest with every imported record ID under batch `defense-2026-10-16-v1`.

Existing active Seekers, supervised Helpers, their Advisers and Professionals own the sample history. Up to six Helpers, twenty Seekers and two Professionals are used in ascending ID order. Existing rows are never updated or deleted. Accounts, passwords, availability, duty schedules, current readiness, verification, competency scores and general account consent decisions are untouched. No identity-vault details are generated. Historical referral consent/review records are clearly marked as simulated; they are not real decisions by those users.

Sample history will contribute to ordinary dashboard/report totals in this shared dummy database. Existing competency calculations are not altered and no new competency assessment is manufactured. There are no live seeded queues/emergencies, scheduled upcoming appointments, emails or pop-up notifications.

## Check after deployment

1. Sign in with the existing accounts. Select the last 30 days on dashboards/reports.
2. Check session history for `[DEMO defense-2026-10-16-v1]` report/message text and Professional history for the completed sample referrals.
3. Confirm the existing live requests still have their original status and no new emergency popup or email was generated by import.
4. Re-deploy with the flag still true once if desired: logs should say `already exists; skipped`, with no duplicate batch.
5. Demonstrate real-time behavior using the normal UI: complete readiness on a valid duty, create a fresh request, chat, raise a referral/emergency, and record the decisions. Historical rows do not simulate live delivery.

The exact defense time is unnecessary for this historical import. Duty/readiness and fresh requests are still handled through the existing workflow when presenting. Do not delete the audit manifest to rerun the import: it is the duplicate-prevention record and cleanup inventory.
